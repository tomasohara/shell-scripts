This directory contains data from the Bash2Py repository at the University of
Waterloo. This uses a custom Bash interpreter to do the translation.
Due to problems with the latest source (circa Jan 2017), an older version
of the code was used (circa Jul 2014): 
    https://www.swag.uwaterloo.ca/bash2py/downloads/2.3/bash2py-2.3.zip

Additional quirks across the 44 test pairs (via Antigravity / Gemini 4 Argon Medium):

1. File / Directory Anomalies:
   - `open_source.zip.py`: orphan translation of a binary `.zip` file (`PK\x03\x04...`) with no `.bash` counterpart.
   - `translate_log.bash`: empty (`0` bytes), producing a 2-line stub in `translate_log.py`.

2. Python Syntax Errors in Generated `.py` Files (24 of 44 `.py` files fail `ast.parse`):
   - Stack pointer / binary garbage leaks on `$(( ((`...`)) ))` (2 files):
     - `secretNumber.py` (`\t_\x8b\xff\x7f`)
     - `ext_cmd_with_output.py` (`\xf0\x81\xe3f\xff\x7f`)
   - Escaped quotes outside string literals (`(\"...\")`) from `$((...))` (4 files):
     - `1.py`: `print("a" + str((\"1+2\")) + "b")`
     - `a.py`: `x=(\"1+2\")`
     - `b.py`: `x=(\"a+1\")`
     - `while2.py`: `x=( x +\" 1 )`
   - Corrupted `$[...]` / `let` arithmetic emitting unbalanced quotes or invalid targets (6 files):
     - `backticks.py`, `master.py`, `while1.py`: `SUM=[SUM +" SCORE]` (from `SUM=$[$SUM + $SCORE]`)
     - `raid.py`: `"index" = index +1"`
     - `let.py`: `"a +"= 1` and C-style `a++` / `++a` left verbatim
     - `test2.py`: `count++` left verbatim
   - Doubled quotes `""y""` (2 files, plus `""q""` in `backticks.py`, `master.py`, `while1.py`):
     - `calc1.py`, `calculator.py`: `while (i == ""y"" ):`
   - Flag arguments with `=` split into invalid keyword assignments `"--flag"="/val"` (2 files):
     - `ebuild.py`: `_rc = subprocess.call(["./configure","--prefix"="/usr"])`
     - `line_continuations.py`: `print(...,"--with-openssl"="/lib64")`
   - Shell pipelines translated into bitwise-OR assignment `_rc = ... | _rc = ...` (2 files):
     - `home.py`, `home1.py`: `_rc = subprocess.call(...) | _rc = subprocess.call(...)`
   - Unquoted glob `*` and punctuation `!` emitted verbatim into Python expressions (5 files):
     - `for.py`: `for i in [*]:` (from `for i in *`)
     - `echo.py`, `logStuff.py`, `temp_file.py`: `***"ABC"***` (from `***ABC***`)
     - `for1.py`: `print("DONE"!)` (from `echo DONE!`)

3. Semantic Bugs in Syntactically Valid `.py` Files (remaining 20 files):
   - Variables turned into string literals in comparisons (`"$VAR"` or `"VAR"` instead of `VAR`):
     - `test.py`: `if ("$SCORE" < "1" ):`
     - `secretNumber.py`: `while ("guess" != "secretNumber" ):`
   - Legacy `$[...]` arithmetic translated as Python list literals `[...]`:
     - `if.py`: `idealweight=[height - 110]` (where `height` is `str(sys.argv[2])`, causing `TypeError` and wrapping in a list)
     - `sum.py`: `SUM2=["SUM+SUM1"]` (from `SUM2=$[SUM+SUM1]`)
   - Brace expansion `{3..6}` wrapped in a nested list `[range(3,7)]`:
     - `range.py`: `for i in [range(3,7)]:` (iterates once over the `range` object rather than its elements)
   - Adjacent string concatenation turns into unary `+` (`str(x) +  + str(y)`):
     - `comments.py`: `print(str(x) +  + str(y))` (`TypeError: bad operand type for unary +: 'str'`)
   - Shell `eval` translated as Python `exec(...)` on shell commands:
     - `ian.py`: `exec("ls -la")`
   - Python 2-only builtins (`raw_input`, `file`):
     - `cleanup.py` uses `stdout=file('messages','wb')`
     - `case.py` (and 7 other files) use `raw_input()`
